# 个人贷款违约预测项目后续行动执行手册

## 1. 项目目标与最终成果

### 1.1 项目主题

本项目围绕“个人贷款违约预测：面向不平衡与业务代价的系统性改进”展开。核心任务是基于个人信贷数据预测借款人是否会发生违约，并在建模过程中重点处理两个现实问题：

- 类别不平衡：违约用户通常占比较低，模型容易偏向预测为非违约。
- 业务代价不对称：漏判违约用户和误拒正常用户带来的业务损失不同，不能只依赖通用分类指标。

项目不应停留在“比较几个模型谁的分数更高”，而应形成一套从数据理解、特征工程、强基线建模、不平衡处理、业务阈值优化到模型解释的完整风控建模流程。

### 1.2 最终目标

最终需要回答以下问题：

- 哪些用户特征与贷款违约风险关系最强？
- LightGBM、XGBoost 等模型在该任务上的基线效果如何？
- 类别不平衡处理是否能提升违约用户识别能力？
- 在不同业务代价假设下，最优预测阈值如何变化？
- 模型预测结果是否可以通过 SHAP 等方法解释清楚？
- 最终方案是否能形成可展示、可复现、可讲述的机器学习实践成果？

### 1.3 最终交付物

建议最终至少形成以下交付物：

- 数据处理产物：字段说明表、缺失值统计表、清洗后训练集与测试集。
- 实验代码：数据预处理、特征工程、模型训练、评估、解释分析代码。
- 实验图表：违约率分布、特征分布、ROC 曲线、PR 曲线、混淆矩阵、代价曲线、SHAP 图。
- 模型结果：多模型性能对比表、不平衡策略对比表、阈值优化结果表。
- 解释分析：全局特征重要性、单样本解释案例、关键变量业务含义。
- 展示材料：最终报告、最终 PPT、Streamlit 或 Gradio 展示界面。

## 2. 总体技术路线

项目建议采用以下主线推进：

1. 数据获取与理解。
2. EDA 与违约率分析。
3. 数据清洗与特征工程。
4. 基线模型构建。
5. 不平衡处理策略对比。
6. 概率校准与业务阈值优化。
7. SHAP 可解释性分析。
8. 扩展模型实验。
9. 最终结果整理与展示系统。

整体逻辑可以概括为：

```text
数据集选择
  -> 数据理解与清洗
  -> 特征工程
  -> LightGBM/XGBoost 强基线
  -> 不平衡策略对比
  -> 概率校准与业务阈值优化
  -> SHAP 可解释性分析
  -> 报告、PPT 与展示系统
```

## 3. 详细执行步骤

### 3.1 第 1 阶段：数据准备

目标：明确数据来源、目标变量、字段含义和基础问题设定。

主要任务：

- 下载 Home Credit Default Risk 数据集，作为主实验数据集。
- 下载 Taiwan Credit Card Default 数据集，作为可扩展性验证数据集。
- 确认每个数据集的目标变量含义。
- 统计样本量、特征数量、违约样本数、非违约样本数和违约率。
- 整理字段说明表，区分数值变量、类别变量、时间变量、ID 变量和目标变量。
- 明确哪些字段不能用于建模，避免数据泄漏。

建议产出：

- `字段说明表.xlsx` 或 `字段说明表.md`。
- 数据集基本信息表。
- 目标变量分布图。
- 数据泄漏风险字段清单。

验收标准：

- 能清楚说明每个数据集的样本规模、违约率和适用场景。
- 能明确主实验数据集和扩展验证数据集的角色。
- 后续成员可以根据字段说明独立理解数据。

### 3.2 第 2 阶段：EDA 与数据清洗

目标：发现数据质量问题，形成可靠的建模输入。

主要任务：

- 统计每个字段的缺失率。
- 分析关键数值变量的分布、异常值和偏态情况。
- 分析关键类别变量的取值数量、频率分布和稀有类别。
- 比较违约组与非违约组在核心变量上的差异。
- 确定训练集、验证集和测试集划分方案。
- 对缺失值、异常值、重复值和无效值进行处理。

重点图表：

- 违约率柱状图。
- 缺失值比例 Top N 图。
- 核心变量分布图。
- 违约组与非违约组对比图。
- 类别变量频数分布图。

建议产出：

- EDA notebook。
- 数据清洗说明。
- 清洗后训练集、验证集和测试集。
- 核心变量分析图。

验收标准：

- 数据清洗规则可解释、可复现。
- 训练集、验证集和测试集划分固定。
- 所有后续实验使用同一套数据划分，保证对比公平。

### 3.3 第 3 阶段：特征工程

目标：构造适合风控建模的稳定特征，提高模型表现与解释性。

主要任务：

- 缺失值处理：数值变量可使用中位数、特殊值或模型兼容方式；类别变量可填充为 `Unknown`。
- 类别编码：根据模型类型选择 One-Hot、Label Encoding、Target Encoding 或原生类别特征支持。
- 数值处理：必要时进行标准化、截尾、分箱或对数变换。
- 比率型特征：构造收入负债比、贷款收入比、年金收入比等金融风控常见衍生特征。
- WOE/IV 特征：作为可选方向，用于增强解释性和传统风控味道。
- 特征筛选：删除高缺失、低方差、强泄漏或明显无业务意义的变量。

建议产出：

- 特征工程代码。
- 特征清单。
- 新增衍生特征说明。
- 特征筛选记录。

验收标准：

- 每个新增特征都有清晰含义。
- 特征工程流程可以在训练集和测试集上稳定复用。
- 不使用测试集信息进行特征选择或编码拟合。

### 3.4 第 4 阶段：模型基线构建

目标：建立可靠强基线，为后续优化提供参照。

推荐模型：

- Logistic Regression：作为可解释线性基线。
- XGBoost：作为经典梯度提升树对比模型。
- LightGBM：作为主力强基线模型。

评估指标：

- ROC-AUC：衡量整体排序能力。
- PR-AUC：更适合类别不平衡任务。
- Recall：关注违约用户召回率。
- Precision：关注预测为违约用户中的真实比例。
- F1：综合 Precision 与 Recall。
- 混淆矩阵：展示 TP、FP、TN、FN。

主要任务：

- 使用原始不平衡数据训练初版模型。
- 统一训练/验证/测试划分。
- 统一评估函数和输出格式。
- 记录每个模型的关键参数和随机种子。
- 输出模型性能对比表。

建议产出：

- `baseline_results.csv`。
- ROC 曲线。
- PR 曲线。
- 混淆矩阵。
- 模型性能对比表。

验收标准：

- 至少完成 Logistic Regression、XGBoost、LightGBM 三个模型。
- LightGBM 成为后续优化的主要基线。
- 所有模型结果都能复现。

### 3.5 第 5 阶段：不平衡处理策略对比

目标：围绕项目亮点，系统比较不同不平衡处理方法的效果。

推荐策略：

- 原始数据：不做额外处理，作为参照。
- 权重法：使用 `class_weight` 或 `scale_pos_weight`。
- 随机欠采样：减少多数类样本。
- SMOTE：合成少数类样本。
- 阈值移动：在概率输出基础上调整分类阈值。

实验设计：

- 固定模型，例如先以 LightGBM 为主模型。
- 固定数据划分和核心特征。
- 每次只改变一种不平衡处理策略。
- 对比 PR-AUC、Recall、Precision、F1 和混淆矩阵。

建议产出：

- 不平衡策略对比表。
- 不同策略下的 PR 曲线。
- 不同策略下的混淆矩阵。
- 违约召回率与误报数量对比图。

验收标准：

- 能说明哪种策略最适合本项目。
- 不只看分数，还要解释业务影响。
- 能回答“多识别了多少违约用户，同时多误报了多少正常用户”。

### 3.6 第 6 阶段：业务代价优化

目标：把机器学习指标转化为业务决策指标，使项目区别于普通分类实验。

核心思想：

在贷款违约预测中，漏判一个违约用户通常比误拒一个正常用户代价更高。因此模型最终不应固定使用 0.5 作为分类阈值，而应根据业务代价选择阈值。

建议设定：

- FN 成本：实际违约但预测为不违约，代表放贷后可能产生损失。
- FP 成本：实际不违约但预测为违约，代表误拒优质用户带来的机会损失。
- 总业务代价：`总成本 = FN 数量 * FN 成本 + FP 数量 * FP 成本`。

主要任务：

- 设置多组成本假设，例如 FN:FP = 5:1、10:1、20:1。
- 遍历预测阈值，例如从 0.01 到 0.99。
- 计算每个阈值下的混淆矩阵和总成本。
- 找到不同成本假设下的最优阈值。
- 输出代价曲线和阈值推荐表。

建议产出：

- 阈值-业务成本曲线。
- 最优阈值表。
- 不同阈值下的混淆矩阵。
- 业务解释文字。

验收标准：

- 能解释为什么最终阈值不是 0.5。
- 能将模型结果转化为风控决策建议。
- 能在最终 PPT 中形成一个明确亮点页。

### 3.7 第 7 阶段：可解释性分析

目标：解释模型为什么做出高风险判断，提升项目可信度。

推荐方法：

- 使用 LightGBM 的特征重要性作为基础解释。
- 使用 SHAP 进行全局和局部解释。

主要任务：

- 输出全局特征重要性图。
- 输出 SHAP summary plot。
- 选择 2-3 个典型样本做单样本解释。
- 对高风险样本说明哪些特征推动了违约预测。
- 对低风险样本说明哪些特征降低了违约预测。
- 将关键变量翻译成业务语言，而不是只停留在算法术语。

建议产出：

- LightGBM feature importance 图。
- SHAP summary plot。
- SHAP waterfall plot 或 force plot。
- 单样本解释案例。
- 关键特征业务解释表。

验收标准：

- 能解释模型整体依赖哪些变量。
- 能解释单个用户为什么被判为高风险。
- 最终汇报中能把 SHAP 图讲成业务洞察。

### 3.8 第 8 阶段：扩展模型实验

目标：在主线完整后，加入深度学习或表格专用模型作为扩展探索。

可选模型：

- MLP + Embedding。

执行原则：

- 扩展模型不是主线，不能影响 LightGBM 强基线和业务代价分析。

- 若表现不如 LightGBM，也可以作为合理结论：在中小规模表格数据上，GBDT 仍然具有强竞争力。

建议产出：

- 扩展模型性能表。
- 与 LightGBM 的对比分析。
- 深度模型效果不佳时的原因讨论。

验收标准：

- 能说明其优缺点和适用条件。
- 不让深度学习部分喧宾夺主。

## 4. 实验框架

### 4.1 模型维度

| 模型 | 角色 | 说明 |
| --- | --- | --- |
| Logistic Regression | 简单基线 | 可解释性强，作为传统线性模型参照 |
| XGBoost | 强基线 | 经典 GBDT 模型，适合作为 LightGBM 对照 |
| LightGBM | 主模型 | 训练快、效果强，适合作为主要优化对象 |
| MLP + Embedding | 扩展模型 | 用于探索深度学习在表格数据上的效果 |
| TabNet 或 FT-Transformer | 可选扩展 | 用于体现表格深度学习调研成果 |

### 4.2 不平衡处理维度

| 策略 | 目的 | 注意事项 |
| --- | --- | --- |
| 原始数据 | 建立参照 | 容易偏向多数类 |
| 权重法 | 提高少数类损失权重 | 简单稳定，优先尝试 |
| 欠采样 | 降低多数类影响 | 可能损失信息 |
| SMOTE | 合成少数类样本 | 可能生成重叠或不真实样本 |
| 阈值移动 | 调整业务决策边界 | 必须结合 Precision、Recall 和业务成本解释 |

### 4.3 评估维度

| 指标 | 用途 | 说明 |
| --- | --- | --- |
| Accuracy | 基础参考 | 不适合作为不平衡任务主指标 |
| ROC-AUC | 排序能力 | 可作为整体性能指标 |
| PR-AUC | 少数类识别能力 | 对违约预测更重要 |
| Recall | 违约召回 | 衡量识别出多少真实违约用户 |
| Precision | 预测准确性 | 衡量预测为违约的用户中有多少真实违约 |
| F1 | 综合指标 | 平衡 Precision 与 Recall |
| 混淆矩阵 | 错误类型 | 明确 TP、FP、TN、FN |
| 业务代价 | 决策价值 | 最贴近风控实际目标 |

### 4.4 解释维度

| 方法 | 用途 | 输出 |
| --- | --- | --- |
| Feature Importance | 快速查看重要变量 | 特征重要性柱状图 |
| SHAP Summary Plot | 全局解释 | 变量对预测方向和强度的影响 |
| SHAP Waterfall Plot | 单样本解释 | 单个用户风险来源 |
| 业务解释表 | 汇报转化 | 将模型变量翻译为金融风控语言 |

## 8. 风险与注意事项

### 8.1 指标风险

- 不要只看 Accuracy。类别不平衡场景下，高 Accuracy 可能只是模型大量预测为非违约。
- PR-AUC、Recall、Precision、混淆矩阵和业务代价更能体现项目价值。
- 汇报时应解释为什么选择这些指标。

### 8.2 实验风险

- 不同模型必须使用相同训练/验证/测试划分。
- 不平衡处理只能在训练集上拟合，不能把测试集信息泄漏进训练过程。
- SMOTE 等采样方法必须放在交叉验证或训练流程内部，避免数据泄漏。
- 所有随机种子应固定，方便复现。

### 8.3 主线风险

- 不要让深度学习模型喧宾夺主。
- 先保证 LightGBM 强基线、不平衡策略和业务代价分析完整。
- 如果扩展模型效果一般，也可以作为合理结论，不需要强行包装。

### 8.4 汇报风险

- 当前 PPT 中仍有模板占位文字，需要后续替换。
- 方法介绍页比例偏高，最终汇报应增加真实实验结果。
- 所有图表都需要能追溯到具体实验设置。
- 不能只展示模型分数，还要讲清楚业务含义。

## 9. 最终汇报建议主线

最终汇报建议围绕以下故事展开：

1. 个人贷款违约预测是典型金融风控问题，类别不平衡和业务代价不对称是核心难点。
2. 我们选择真实金融数据集，完成数据清洗、特征工程和强基线建模。
3. 在普通分类指标之外，我们重点关注 PR-AUC、Recall、混淆矩阵和业务代价。
4. LightGBM/XGBoost 提供了稳定强基线，权重法、采样法和阈值移动进一步改善违约识别。
5. 通过业务代价函数，我们将模型概率转化为更合理的贷款审批阈值。
6. 通过 SHAP，我们解释了模型判断高风险用户的依据。
7. 最终形成一套可复现、可解释、面向业务决策的违约预测流程。

一句话总结：

> 本项目不是单纯追求分类分数，而是面向违约识别、类别不平衡和业务损失，构建一套完整的金融风控机器学习流程。
